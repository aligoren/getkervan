MCP servers from a YAML spec, or from TypeScript

Kervan is a framework for Model Context Protocol servers. Describe HTTP tools in a kervan.yaml file and serve them with one command, or write tools in TypeScript on the official MCP SDK. The same validation, limits and security checks apply either way.

Why Kervan

  • A spec or code

    HTTP APIs become tools from a YAML file with no code. When you need logic, write the tool in TypeScript with Zod schemas.

  • On the official MCP SDK

    A thin layer over @modelcontextprotocol/server: the protocol is the SDK's, not a rewrite.

  • MCP 2026-07-28, statelessly

    Every request carries its own context; server/discover replaces the handshake. Clients of the 2025 revisions are served too.

  • Typed and checked

    Arguments are validated before your handler runs; only ToolError messages reach the client, other errors are masked with a reference.

  • Safe defaults

    Timeouts, size limits, rate limits, Host and Origin checks, and for spec tools SSRF protection and secret redaction.

  • Nothing to lock you in

    MIT licensed. Specs are plain YAML in your repository, and a Studio server exports as the same file.

Kervan Studio, if you want a web UI

Studio is an optional, self-hosted web app: people write specs in the browser, keep upstream API keys in an encrypted vault, publish versions and roll them back, and MCP clients connect through one gateway with per-server API keys. Nothing is locked in: every server exports as kervan.yaml and runs with kervan run.

Read the Kervan Studio documentation or follow the guide to self-hosting a multi-user MCP gateway.

Security by design

Each of these is implemented and covered by tests, including tests that break the check on purpose and expect a failure.

  • SSRF protection

    Spec tools reach public addresses only. DNS is resolved once and the connection pinned to the checked address; redirects are refused unless allowed, then checked again; cloud metadata addresses are always refused.

  • Encrypted secrets

    Studio encrypts secret values with AES-256-GCM under a master key you keep. Results, errors and logs are redacted of them, in every encoding Kervan knows.

  • Users and roles

    Admins and members, sessions that end on password or role changes, throttled sign-ins, and the admin's own password for sensitive changes.

  • CSRF and origin checks

    Every change needs the exact origin, a JSON body and the session's CSRF token; the gateway checks Host and Origin.

  • Sandboxed select

    select expressions run in a separate process: empty environment, memory limit, the tool's timeout, no network, no file writes, no child processes.

  • Audit trail

    Studio records sign-ins, publishes, secret and key changes in a log the database refuses to change or delete; never a password, key or secret value.

The details, including what is out of scope: the framework security model and the Studio threat model. Report vulnerabilities privately to {{ site.Params.security }} (security.txt).
